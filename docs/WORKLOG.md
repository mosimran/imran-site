# Work log

Append-only, newest last. One entry per task, generated by `npm run worklog` so the
shape does not drift.

Four fixed fields. **What changed**, then:

- **Validated** the check that was actually run, including deliberate failures
- **Deployed** what is live, and where
- **Next** the task that follows

A log entry that only says what was built is a changelog, and there is already a
changelog. When a task fails validation the entry still gets written, with what failed
and why, and the next task does not start.

Late in the build this file becomes the source for Appendix A, Document History, so
the document's revision log and the repository's work log are one record kept once.
